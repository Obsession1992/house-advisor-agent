技术架构 // Hybrid Architecture Design

USER INPUT
"海狮沟1楼73㎡ 190万 简装 1998年"
↓
AGENT LAYER — Prompt 软逻辑
意图识别 流程编排 结果整合
↓
WORKFLOW — 硬逻辑
财务计算
评分引擎
数据校验
PLUGIN — 数据检索
板块均价
地铁/学校
政策信息
↓
OUTPUT — 决策报告
六步法报告 · 风险提示 · 签约建议
● Agent 层 Prompt 软逻辑
负责意图识别、流程编排和结果整合。通过 Prompt 工程实现灵活的对话理解和决策推理
● 工作流层 硬逻辑计算
财务计算、评分引擎等确定性逻辑。用工作流保证计算精度，避免 LLM 幻觉
● 插件层 公开数据检索
检索公开数据（板块均价、地铁距离、学校信息等），为决策提供数据支撑
/* 为什么选择混合架构？ */
✓ Agent 处理模糊意图 → 灵活应对多样化输入
✓ 工作流处理精确计算 → 杜绝 LLM 数值幻觉
✓ 插件获取实时数据 → 不依赖训练数据，结果可验证
📋 架构决策记录（ADR）
问题 装修成本单位换算错误（130万 vs 13万） 备选 纯Prompt修复 vs 工作流固化 决策 工作流固化 — 财务计算是确定性逻辑，不应由LLM推断 效果 计算类错误归零 ✓

迭代过程 // Iteration History (5轮 · 14用例)

a3f7c2d 🐛 fix: 修复装修成本单位换算Bug（130万→13万） 2026-05-18
问题
装修成本估算输出130万（73㎡×1500元÷10000=10.95万，LLM输出130万）
根因
Agent 直接生成数值，未经工作流校验；单位换算（元→万元）被跳过
修复
将装修成本计算迁入工作流节点，强制使用精确公式而非 Prompt 推断
验证
3个测试用例全部通过：毛坯/简装/精装场景输出均正确 ✓
b8e4f1a ✨ feat: 新增极端低价房源预警机制 2026-06-02
问题
单价远低于板块均价的房源未触发预警，可能误导用户
根因
原始规则未覆盖"价格异常低"场景，缺少与板块均价的对比逻辑
修复
新增规则：当房源单价 < 板块均价50%时，触发"价格异常"红色预警
验证
武林壹号案例触发预警，输出"单价偏低52%，需核实产权状况" ✓
c1d9e3b ✨ feat: 新增房龄数据自动校验与异常标记 2026-06-15
问题
用户输入"2025年建"等不合理房龄数据，系统未识别异常
根因
工作流未校验输入数据的合理性范围
修复
新增校验节点：房龄 > 50年 或 建成年份 > 当前年份 → 标记异常并要求确认
验证
边界用例测试通过，异常输入均正确标记并提示用户确认 ✓

局限性与 Roadmap // Limitations & Future Plans

⚠ 当前局限性

⊘ 数据源有限：板块数据依赖公开信息，精度和实时性受限，无法获取真实成交数据
⊘ 单城市限制：当前规则基于杭州市场设计，不同城市的参数需要重新校准
⊘ 多轮对话局限：极端多轮场景可能出现上下文丢失，长对话记忆待优化
⊘ 缺少用户反馈闭环：尚未建立用户实际购房结果的回流验证机制
⊘ Step 0 未实现：宏观趋势分析（是否该买房）尚处于规划阶段
⊘ 唯一未通过测试：极端多轮对话中的上下文丢失，14用例中1例未通过（已知局限）
